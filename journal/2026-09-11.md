## 2026-09-11_14:57:24 - Emit the @osg/model document domain

### What happened

The output of `triplifier-md` now follows the document domain of the `@osg/model` SHACL model, `shapes/document.ttl`. The domain was designed in the same session, together with a rewrite of the whole model into seven domain files. The library was changed after the shapes, and its real output was validated against them: zero violations.

The structural change, in one table:

| Before | After |
|---|---|
| `urn:name:X.md` untyped document node, `urn:token:about` | `document:File`, `schema:about` |
| `urn:name:X` concept, untyped | `resource:Resource` |
| `urn:name:X%23H` concept with `urn:meta:raw`, `depth`, `line` | `resource:ResourceReference`: source the note, an Obsidian fragment selector, an RFC 5147 line range and a text quote per occurrence |
| `urn:token:_` for prose links | `dct:references` |
| `urn:code-block:<lang>` and `urn:blockquote` literals | parts via `schema:hasPart`: references typed `schema:SoftwareSourceCode` or `schema:Quotation`, with line range and quote |
| `title`, `tags`, `created`, `modified` as `urn:token:` | `rdfs:label`, `schema:keywords`, `dct:created`, `dct:modified` |

`canonical-md` exports the vocabulary (`vocab`, `FRONTMATTER_TERMS`), `splitHeadingName` and `lineRange`. `urn:meta:` helpers and `UNTYPED_TOKEN` are gone. The spec `spec/document-model.md` was rewritten. All three package suites pass (19, 25, 30).

Two defects were fixed on the way. `[[#Heading]]` used to strip the `#` and resolve to `urn:name:Heading`, a foreign note; it now resolves within the current note, and `[[#<note name>]]` or `[[#<first H1>]]` to the note itself. `triplify()` counted the empty line after a final newline as a content line, so an unclosed fence at end of file got one line too many; the stream path did not. Both paths now agree.

### Decisions

- **Heading identity is name plus fragment, source the note by name.** A `[[Bob#Bio]]` link anywhere emits the complete reference for `urn:name:Bob%23Bio`, because that is all a heading's identity takes. Triplification stays order-independent. Line numbers come only from the owning file.
- **Location and content are selectors, not predicates.** RFC 5147 counts line positions from 0, so a heading on 1-based line 10 is `line=9,10`. Depth is not emitted; it is the count of `#` in the quoted line.
- **No name normalisation.** The IRI must stay reversible. A link must match the file's casing. The model records the rule and cannot check it.
- **schema.org is `https://schema.org/`.** schema.org's editorial form. This library already used it; the model and the file triplifier used `http://` and change.
- **The File IRI carries no pattern.** This is a library, the file triplifier rewrites the document subject, so the model must not enforce `file://`.
- **Structural `rdf:type` is emitted; domain `rdf:type` is still deferred.** The old "no rdf:type at all" rule referred to domain types from fields. The model needs `document:File`, `resource:Resource`, `resource:ResourceReference`, the selector classes and the part kinds, and those are emitted.
- **Fields stay `urn:token:` and are unconstrained.** SHACL cannot constrain an open predicate namespace. The model says so instead of pretending.

### What is red now

The file triplifier that wraps this library links this workspace directly and picked up the change at once: 5 of 88 tests fail. Its stages `relation-labels.js` and `repo-readme/rewrite.js`, its vocabulary and `config/namespaces.json` still expect `urn:token:_`, `urn:token:about` and `http://schema.org/`. That migration was left out of scope on purpose; the plan is to publish a new dot-triples version first.

### What seemed important to the user

Being sure of the core design before code: the heading-as-reference decision was asked to be elaborated twice, and the code-block decision was reframed by the maintainer as "they are also selections", which is what shaped parts as references. Reversibility of names, and the library-versus-triplifier boundary.

### Friction

Two shacl-engine 1.1.2 defects shape the SHACL: several `sh:not` values crash it, and `sh:qualifiedValueShape` under `sh:node` checks the wrong node. A reproduction and patch exist; a pull request upstream is planned separately. Until then, selectors are constrained with `sh:in` on every `rdf:type` value.
