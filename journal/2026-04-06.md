## 2026-04-06_12:54:08 - Fix invalid IRI code point '#' in section headings

### What happened

The `triplifier-doctor.sh` script was run and reported failures across multiple repositories. All failures shared the same root cause: Oxigraph rejecting N-Triples with `Invalid IRI code point '#'`.

**Root cause**: In `sectionIri()` (and its equivalent in the installed version), heading text was encoded with `encodeURI()` before being appended after the `#` fragment separator. `encodeURI` does not encode `#`, so headings like:
- `## Subsection #person`
- `## [[Flow based programming#Rete.js]]`
- `## Handling \`#Heading\` and Block References`
- `## addg(value) ⇒ ... &#124; ...` (HTML entity `&#124;` contains a literal `#`)

...all produced IRIs with two `#` characters, e.g. `<urn:name:file#Subsection #person>`, which is invalid.

**Fix**: Changed `encodeURI(heading)` to `encodeURIComponent(heading)` in both:
1. `src/triplify.js` in this working repo
2. `src/triplifier.js` in the installed repo at `/home/cvasquez/claude/osg/osg-triplifier`

`encodeURIComponent` encodes `#` as `%23`, keeping the IRI valid (one `#` as fragment separator). It's fully reversible via `decodeURIComponent`.

A test was added covering both the direct `#` in heading text case and the wiki-link-with-anchor case.
